# Prefácio

## Finalidade

O ArreioWork nasceu da necessidade de organizar sistemas de software por meio de uma linguagem comum, capaz de aproximar pessoas, conceitos e tecnologia.

Ao longo da evolução da engenharia de software, diferentes linguagens, frameworks, arquiteturas e metodologias surgiram para resolver problemas específicos. Embora tenham contribuído significativamente para o desenvolvimento de aplicações cada vez mais complexas, também introduziram um novo desafio: **cada tecnologia passou a criar seu próprio vocabulário**.

Termos como *Controller*, *Service*, *Repository*, *Hook*, *Worker*, *Provider*, *Middleware*, *Watcher* e muitos outros passaram a representar conceitos semelhantes, mas com nomes, responsabilidades e interpretações diferentes conforme o ecossistema utilizado.

Essa diversidade é natural, porém dificulta a comunicação entre equipes, aumenta a curva de aprendizado e torna a arquitetura dependente da tecnologia escolhida.

O ArreioWork propõe uma abordagem diferente.

Em vez de iniciar pela tecnologia, inicia pelos conceitos.

Independentemente da linguagem utilizada, todo software precisa existir, comunicar-se, armazenar conhecimento, executar ações, responder a eventos e evoluir ao longo do tempo.

Esses comportamentos são universais.

O ArreioWork busca descrevê-los utilizando uma linguagem própria, consistente e independente de implementação.

---

# Propósito

O propósito do ArreioWork é estabelecer um modelo conceitual para construção de software.

Seu objetivo não é substituir linguagens de programação, frameworks, bibliotecas ou padrões arquiteturais.

Seu objetivo é fornecer uma forma comum de compreender sistemas antes mesmo de sua implementação.

No ArreioWork, nomes não existem apenas para identificar componentes.

Eles existem para comunicar intenção.

Quando duas pessoas utilizam a mesma linguagem conceitual, tornam-se capazes de compreender um sistema independentemente da tecnologia empregada.

---

# A Linguagem do Universo

O ArreioWork utiliza uma metáfora inspirada na organização de um universo.

Essa escolha não possui finalidade estética.

Ela possui finalidade pedagógica e arquitetural.

Um universo é composto por elementos organizados, cada um com identidade, propósito, responsabilidades e relações claramente definidas.

Da mesma forma, um sistema de software pode ser compreendido como um conjunto organizado de elementos que cooperam para atingir um objetivo comum.

Nesse modelo:

* Um software é representado por um **Planeta**.
* Uma área de conhecimento é representada por uma **Constelação**.
* Os componentes que executam ações são **Habitantes**.
* As formas oficiais de comunicação são **Portais**.
* O conhecimento persistente é armazenado em **Livros**.
* Os acontecimentos relevantes tornam-se **Crônicas**.
* As regras que governam o comportamento são chamadas de **Leis**.

Esses nomes representam conceitos permanentes.

A implementação desses conceitos pode variar conforme a tecnologia utilizada.

---

# Independência Tecnológica

O ArreioWork não pertence a uma linguagem de programação.

Não pertence a um framework.

Não pertence a um sistema operacional.

Pode ser aplicado em aplicações escritas em Python, TypeScript, Java, C#, Go, Rust, Kotlin ou qualquer outra tecnologia capaz de representar seus conceitos.

Da mesma forma, um Planeta pode utilizar REST, GraphQL, WebSocket, filas de mensagens, RPC ou qualquer outro mecanismo de comunicação, desde que respeite os princípios definidos pelo framework.

O ArreioWork descreve **o que um sistema é**, não **como uma tecnologia específica deve implementá-lo**.

---

# Organização antes da Complexidade

A complexidade é uma característica natural de sistemas em evolução.

Ela não pode ser eliminada.

Pode apenas ser organizada.

O ArreioWork parte do princípio de que arquiteturas bem definidas reduzem o custo cognitivo necessário para compreender um software.

Quanto menor o esforço para entender um sistema, maior sua capacidade de evoluir de forma segura.

Por esse motivo, cada conceito do ArreioWork possui uma única definição oficial.

Ambiguidades são tratadas como oportunidades de refinamento da linguagem.

---

# Conhecimento Compartilhado

Software é construído por pessoas.

Pessoas entram em equipes.

Pessoas deixam equipes.

Tecnologias evoluem.

Projetos mudam de direção.

O conhecimento, entretanto, não deve desaparecer com essas mudanças.

O ArreioWork considera que um sistema deve ser capaz de comunicar sua organização de forma clara para qualquer pessoa que venha a interagir com ele.

O código é parte desse conhecimento.

A arquitetura é parte desse conhecimento.

A documentação também é parte desse conhecimento.

Todos devem contar a mesma história.

---

# Evolução Contínua

O ArreioWork não é um modelo fechado.

Novos conceitos poderão ser incorporados ao longo do tempo.

Novas tecnologias poderão ampliar suas possibilidades de implementação.

Entretanto, toda evolução deverá preservar a coerência do universo conceitual estabelecido pelos Fundamentos.

A expansão do framework deve ocorrer por evolução, nunca por ruptura.

---

# Escopo deste Documento

Este Prefácio não estabelece regras.

Não define leis.

Não apresenta convenções.

Seu objetivo é contextualizar o leitor e explicar por que o ArreioWork existe.

Os documentos seguintes apresentarão, de forma progressiva, os princípios, axiomas, leis e convenções que estruturam este universo.

Compreender este propósito é o primeiro passo para compreender todo o restante do ArreioWork.
